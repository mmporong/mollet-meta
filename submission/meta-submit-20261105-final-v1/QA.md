# 예상 질문과 답변

## Meta 모델이 맡는 일은 무엇인가?

Muse Spark는 자연어 요구와 상태 정보를 제한된 조건 스키마로 작성한다. SAM은 영상에서 로봇 위치를 반환한다. PASS·FAIL·UNKNOWN 계산은 Python 판정기가 원본 상태 값과 시간 규칙으로 수행한다.

## Meta 도구를 실제로 호출했나?

그렇다. 2026년 11월 4일에 Muse Spark 1.3과 SAM 3.1을 각각 한 번 호출했고, 두 요청의 완료 상태와 요청·응답 해시를 보존했다. Spark는 H1 조건을 생성했고 SAM은 625개 관측 중 624개에 위치를 반환했다.

## 8초 조건은 8초 동안 계속 자세를 유지한다는 뜻인가?

아니다. 0초부터 판정을 시작해 8초 안에 `up_axis_z >= 0.8`을 만족하기 시작하고, 그 상태를 0.5초 유지하는 조건이다. 실제 H1 결과는 0.0~0.5초 PASS다.

## SAM의 624/625는 추적 정확도인가?

아니다. 위치 결과가 연결된 관측 수다. 정답 박스나 마스크와 비교하지 않았으므로 정확도·IoU·성공률로 표현하지 않는다.

## 조건 PASS가 계단 주행 전체 성공이나 정책 향상을 뜻하나?

아니다. 선택한 조건과 관측 구간의 판정이다. 전체 주행 성공, 회복 성능, 정책 품질을 나타내는 지표가 아니다.

## 영상 기반 Spark 가설과 재검토도 실제 결과인가?

코드 경로와 CPU 검증은 있다. 새 영상 모델 추론과 실제 Spark 재검토는 실행하지 않았으므로 발표에서는 실제 결과로 제시하지 않는다. 데모 근거는 기존 인증 요청에서 저장된 Spark 조건 응답과 SAM 위치 응답이다.

## 보상 수정과 정책 재학습으로 성능이 좋아졌나?

아니다. 확인된 가설을 기존 교정 원장에 제안으로 연결하는 경로는 구현했지만, 새 교정 적용·정책 재학습·GPU 실행·회복 성능 측정은 수행하지 않았다.

## 저장된 Meta 결과를 이어서 보는 것은 새 호출인가?

아니다. 저장된 실제 응답, 공급자 실행 영수증과 원본 영상·상태 값을 대조한 뒤 로컬 화면에 복구하는 재생 경로다. 키가 없어도 기존 근거를 확인할 수 있지만 새 인증이나 새 모델 추론으로 기록하지 않는다. Chrome 검증에서 복구 전후 모델 호출 수는 2회로 같았고 예약 예산도 바뀌지 않았다.

## 복구 화면에서 무엇을 검증했나?

Chrome 156.0.8078.80에서 10개 검사를 모두 통과했다. H1 영상 재생과 SAM 위치 오버레이, 625개 상태와 624개 위치의 결합을 확인했다. 원래 Spark 조건은 0.0~0.5초 PASS였다. 사용자가 8초 유지로 바꾼 조건은 0.0~8.0초 PASS, 더 엄격한 조건은 FAIL이었다. Go2 기록의 12.48초 수동 조건도 FAIL이었다. 편집한 JSON을 다시 불러오면 값은 유지되고 승인 상태는 초기화됐다. 페이지 오류는 없었고 관련 CPU 검사 142개가 통과했다.

## 어떤 데모 영상을 제출하나?

v2 영어 자막판을 기본 파일로 사용한다. 경로는 `submission/meta-recovery-demo-20261105-v2/mollet-meta-recovery-demo-180s-en-captioned.mp4`, SHA-256은 `aaf51142b442f4957a7580214033a86677bdf1cf32a0b02fea7bcbb875d32f57`이다. 길이는 180초이며 전체 디코드를 통과했다. 한국어판 SHA-256은 `94177579127d018a6ebd9a184feac19260458ae71005efea5f0ef129ce79efcb`이다. v1은 영문 자막 배치 문제 때문에 제출 후보에서 제외한다.

## 공식 제출 폼을 모두 확인했나?

아니다. 최신 제출 링크를 별도 headless 프로필에서 열었을 때 `https://cerebralvalley.ai/auth/login`으로 이동했고 Google·이메일 로그인 화면까지만 확인했다. 로그인된 사용자 프로필에 연결하지 못해 실제 필드명·필수 여부·글자 수는 확인하지 않았다. 답변 파일은 공식 필드 매핑이 아니라 답변 은행이다.

## 기존 프로젝트와 이번 기여는 어떻게 구분하나?

기존 Mollet은 RL 실패 진단·회복 평가 기반과 계단 기록을 제공한다. 해커톤 기여는 Meta 조건 저작, 영상 위치 결합, 시간 판정, 검토와 증거 내보내기다. 기존 정책 학습과 회복 결과를 새 Meta 성과에 더하지 않는다.

## 재사용한 기존 프로젝트가 규정에 맞나?

공개 규정에서 원본성·소유권·비침해와 오픈소스 라이선스 준수 조건을 확인했다. 기존 프로젝트 재사용을 명시적으로 허용하거나 금지하는 조항은 찾지 못했다. 따라서 기반 코드와 해커톤 신규 기여를 분리해 설명하고, 로그인 폼의 추가 확인 항목과 최신 규정을 제출 전에 다시 대조한다.

## 비밀키와 저장 응답은 어떻게 다루나?

비밀키 원문은 저장소와 내보내기 파일에 넣지 않는다. 제출 데모는 저장된 실제 응답을 사용하며, 응답 파일만으로 공급자 인증이나 실행 권한을 새로 만들지 않는다.

## 관측이 부족하면 어떻게 하나?

결측, 큰 시간 간격, 추적 단절이나 관측창 부족이 있으면 UNKNOWN으로 남긴다. 근거가 없는 구간을 PASS로 채우지 않는다.
