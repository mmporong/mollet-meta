Project name
Mollet

One-line description
Turn a robot behavior request into a measurable condition, locate the robot in its video, and inspect the exact interval that satisfies the condition.

Problem and intended users
Robotics developers replay recorded experiments to check whether a robot did what they intended. A reward curve does not identify the moment a posture requirement was met or lost. Mollet lets the developer express that requirement and check it against the recorded state, alongside the video.

How it works
Muse Spark 1.3 converts a natural-language request into a restricted JSON behavior contract. SAM 3.1 locates the humanoid in the corresponding video. A deterministic evaluator checks the contract against timestamped robot state. The export keeps the condition, video hash, observations, review record and result together.

Use of Meta tools
We made authenticated Meta Model API requests to Muse Spark 1.3 and SAM 3.1. Spark generated a condition requiring the H1 robot to reach an upright alignment of at least 0.8 within eight seconds and maintain it for half a second. SAM returned robot locations for 624 of the clip's 625 observation frames. This count measures returned tracking coverage, not tracking accuracy.

Demonstrated result
The generated H1 condition passes over the interval from 0.0 to 0.5 seconds. The saved JSON reproduces the same result when evaluated again. The workbench also includes recorded H1 and Go2 stair runs; state-backed examples support time conditions, while examples with summary data show that summary without inventing a time series.

What was built for this hackathon
The Meta contribution is a behavior-authoring workbench: natural-language contracts from Muse Spark, SAM video locations, temporal condition evaluation, review and evidence export. It builds on an existing robotics project and its recorded stair datasets. The existing RL training and recovery-diagnosis system is background infrastructure. The submitted Meta work does not claim a newly trained policy or a new recovery result.

Technical approach
Python serves a localhost workbench and evaluates a validated condition schema. JavaScript provides video selection, condition editing and evidence export. Both Meta models use the Responses API. API credentials stay in server memory; a persistent local reservation ledger limits this workbench's requests. Missing state, gaps or insufficient visual evidence remain unknown rather than receiving a fabricated pass.
