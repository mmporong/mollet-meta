# Meta API 실제 동작과 원본 프로젝트 반영 계획

작성일: 2026-11-04. 메인 담당: co_meta.

## 완료 계약

완료는 원본 프로젝트의 실행 화면에서 실제 Spark 응답으로 조건을 만들고, 실제 SAM 응답으로 객체 위치를 붙인 뒤, 상태 판정과 내보내기 파일을 재검증한 경우다. 코드 작성·모의 전송 검사·편집 영상만으로 전체 완료를 기록하지 않는다.

현재 구현 커밋은 `70b173a17dc3c506c273ccbbc79546dbbe656897`, 원본 기준은 `94fe8740277c9ecc556096fa4d00df0ad0bb7749`다. 원본에는 다른 세션의 진행 중인 변경이 있어 그 변경과 `main` 포인터를 보존한다. 원본 작업 디렉터리 반영과 `main` 이력 병합은 별도 상태로 표시한다.

## 작업과 수용 조건

| ID | 작업 | 완료를 증명할 결과 | 현재 상태 |
|---|---|---|---|
| P1 | 계정·키·크레딧 확인 | 기존 키를 서버에 설정하고 사용자가 확인한 Billing 크레딧·결제수단과 US$1 이하 예산 기록 | 차단: 로컬·WSL 기존 설정에 Meta 키 없음, 브라우저 native pipe 연결 불가 |
| P2 | 실제 Spark·SAM 한 사례 실행 | H1 상행 원본의 Spark 조건 생성·SAM `humanoid robot` 추적 응답, 원문과 request/response SHA, provider ID, 예산 예약 기록 | P1 대기 |
| P3 | 화면 적용·판정·내보내기 | 조건 수정/의미 확인 초기화, bbox 표시, 저장 수치 판정, 내보낸 JSON을 다시 읽어 같은 판정·영상 SHA 확인 | 실제 응답·브라우저 연결 대기 |
| P4 | 원본 프로젝트 적용 | 원본 디렉터리에 Meta 패키지·검사·문서·근거 파일 반영, 해당 위치의 관련 80개 검사와 CLI/HTTP 확인, 원본에서 실행하는 서버 | 진행 |

실행 순서는 P1 조사와 P4 적용을 병행한 뒤 P2 → P3다. 계정 입력이 없으면 P2를 모의 응답으로 대체하지 않는다. 원본 이력 변경이 다른 세션의 실행 결합을 바꿀 수 있어 이번에는 `main` HEAD를 이동하지 않고 추가 기능 경로만 적용한다. 변경 내용은 Meta 기능 브랜치에 커밋해 보존한다.

## 실행 범위

- 허용: 기존 키의 비노출 조회, 로컬 작성·검증·커밋, 원본의 Meta 추가 경로 반영, 확인된 지원 크레딧과 앱 예약 예산 안의 명시적 모델 요청.
- 키: Windows 환경변수, 문서에서 지정한 기존 Windows/WSL 설정 파일, 실행 중인 로컬 앱의 키 설정 여부를 확인한다. 키 원문을 대화·저장소·검증 보고서에 기록하지 않는다.
- 계정: 새 키 발급·카드 등록·계약 수락이 필요하면 해당 작업과 권한 요구를 사용자에게 구체적으로 알린다. 기존 키/계정 확인에 필요한 입력을 기다리는 동안 P4를 계속한다.
- 금지 유지: GPU·실물 로봇 실행·원격 push·대회 신청·제출. 개인 결제나 확인되지 않은 잔액으로 모델을 호출하지 않는다.

## 원본 적용 방법

소스는 `rl-triage-meta`, 대상은 `rl-triage-agent`다. 공통 기준 이후 Meta가 추가한 파일만 개별 경로로 복사하고 기존 파일이 있으면 SHA가 같을 때만 재사용한다. 데이터셋은 원본에 이미 있어 덮어쓰지 않는다.

공용 README·`.gitattributes`·트러블슈팅 문서는 전체 교체하지 않고 Meta 안내/규칙/절만 추가한다. 원본의 기존 tracked/untracked 변경은 되돌리거나 스테이징하지 않는다. 원본 적용 후 패키지 import 경로·파일 SHA·관련 검사·서버 작업 위치를 기록한다.

## 실제 요청의 실패 처리

- 첫 사례는 이미 본 개발 자료이므로 새 정확도·일반화·회복 효과로 보고하지 않는다.
- Spark는 완료된 구조화 JSON과 조건 스키마를 모두 통과해야 적용한다.
- SAM은 `response.completed`와 실제 원문을 보존한다. 빈 탐지는 완료된 빈 결과로 기록하며 객체 추적 성공으로 세지 않는다. 오류·미완료·잘못된 크기·영상 결합은 거부한다.
- 네트워크 실패·예산 소진 시 자동 재시도나 예약 환급을 하지 않는다. 기존 원문과 실패 기록을 남기고 재실행 조건을 명시한다.
- 실제 응답 또는 브라우저 조작이 없으면 그 단계는 차단/미검증으로 남긴다. 완료된 P4를 전체 기능 완료로 확대하지 않는다.

## 최종 납품

현재 상태는 이 문서와 기존 요구사항 문서에서 이어간다. 실행별 근거는 새 `evals/results/meta_original_integration_20261104_v1/` 폴더에 기록하고 덮어쓰지 않는다. 실제 모델 기록은 키를 포함하지 않는 기존 사용자 로컬 run 폴더를 사용한다. 결과 보고에는 P1~P4 상태와 미해결 계정·브라우저 조건, 원본 파일 반영과 `main` 이력 반영의 차이를 표시한다.
